# Workforce — packages cut

One row per signed `.hopkg`: what it carries, how it was built, and where it
went. Newest first. **A package's build provenance is part of the record** — a
binary a property runs is a statement about the tree it came from, so a build
from anything but a clean checkout of HEAD says so here.

**Every command belongs in the row, not only the exports.** 0.3.4's row named
`git archive`, the side-by-side layout and `hopkg`, and left out the `dotnet
publish` invocation. Reproducing it from that row produced a **193 MB payload
and a 68 MB package** — four times the size — because the RID was missing and
six platforms' native libraries came with it.

> **A written procedure that omits a step does not leave a gap. It leaves an
> invention, and a different one each time it is run.**

And record the **method** of verification, not only its result. A result tells
the next person it passed; a method tells them how to make it fail. The one
that matters here is the two-way set assertion against the previously shipped
package — `$extra` and `$missing` as separate checks, because an input
manifest can help with the first and no input boundary reaches the second.
