2 · SHELL-Q37 — the wall FF met. Beneath the bridge, the service's own wire was stood up and called for real. It stops on the platform's shared outbox: event_store.events is created by deployment/database/03-schemas.sql and the platform's own provisioning, not by any migration or test convention an installed application can run. The application's migration correctly creates only jobs. So every operation that announces an event dies at relation "event_store.events" does not exist. Ten rows are held on it, and no double was substituted: a green over an absent dependency is what ADR 0053 forbids.

What was proven anyway. The service's gRPC surface was hosted and called over a real loopback socket — protobuf over HTTP/2, the application's own interceptor, Entity Framework, a real PostgreSQL on a scratch database provisioned the house way. Four rows completed end to end. That layer had no test at all before this round; it now has fourteen, four passing and ten held with their reason named in the code.

Substituted, and named on every row that leans on one: authentication (Identity is down, so a caller is filed where the platform's interceptor would file one), authorization (the Kernel is down, so the recording authorizer stands in and records what each RPC asked), and Master Data (down, so the directory double answers for the property's code and a location's existence). Nothing else: no fixture reaches a handler, and every figure a passing row asserts came back over the wire from the database.
